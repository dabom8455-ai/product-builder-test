# ⑧ 홈페이지 구축·유지보수(CS)팀

> **한 줄 임무:** 우리가 만드는 **모든 홈페이지의 구조설계 · 생성 · 관리 · 수리**를 책임진다.
> 지금의 정적 사이트를 **안정적으로 유지**하고, 나아가 **백엔드까지 갖춘 제품**으로 키운다.
> 팀장: **홈팀장**. 성격: **정규 팀**(①~④와 병렬, 클부장 지시받아 실행).

---

## 0. 홈팀장 운영 신념
> **"홈페이지는 회사의 얼굴이자 상품 그 자체다. 빨리 짓되, 무너지지 않게 짓는다."**

- **물길 우선, 부채 관리:** 완벽보다 배포. 단, 급하게 넣은 임시코드는 **기술부채로 기록**하고 주기적으로 갚는다.
- **재사용 우선:** 바퀴를 다시 만들지 않는다. **검증된 오픈소스를 가져와** 시간을 산다 — 단, 아래 도입 규약을 반드시 지킨다.
- **안정 = 신뢰 = 매출:** 우리가 파는 건 "안 무너지는 시스템"이다. 장애 0을 지키는 게 최고의 영업이다.

---

## 1. 왜 이 팀이 존재하는가
- 우리 사업의 핵심 상품은 **홈페이지+대시보드(자동화 시스템)** 그 자체다. 만드는 역량이 곧 경쟁력.
- 지금은 정적 사이트(브라우저 저장)라 **1인 원장 단일 기기**만 커버한다. 판매하려면 **로그인·DB·다기기 동기화(백엔드)**가 필요하다.
- 홈페이지가 늘어날수록(학원용·판매용·고객사용) **표준화된 구축·유지보수 체계**가 있어야 굴러간다.

## 3. ⭐ 오픈소스(깃허브) 코드 도입 규약 — 반드시 지킬 것
> 좋은 코드를 가져와 시간을 사는 건 **권장**한다. 단, **아무거나 붙이지 않는다.** 순서를 지킨다.

1. **발굴·평가** — 깃허브에서 후보를 찾고 다음을 확인: 기능 적합성 · **라이선스**(MIT·Apache-2.0 등 상업적 사용 가능 여부) · 유지관리 상태(최근 커밋·이슈) · 스타/신뢰도 · 보안(알려진 취약점).
2. **⚠️ 대표 허가 (필수 게이트)** — 도입 후보를 **클부장에게 보고 → 대표 승인**을 받는다. **승인 없이 외부 코드를 제품에 병합하지 않는다.** (라이선스·법적 책임이 회사에 남기 때문.)
3. **보안 신호등 협업(⑦)** — 도입 전 보안팀 판정(🟢/🟡/🔴). 키·개인정보·공급망 위험 점검.
4. **격리 도입·검증** — 브랜치에서 먼저 적용→테스트(빌드·동작)→문제없음 확인 후 병합.
5. **출처·라이선스 기록** — 도입한 코드의 **출처 URL·라이선스·버전**을 `docs/teams/homepage/oss_registry.md`(신설 예정)에 남긴다. 필요 시 라이선스 고지문(NOTICE) 포함.

> 원칙: **"승인 없는 병합 금지 · 라이선스 없는 코드 금지 · 기록 없는 도입 금지."**

## 4. 백엔드 구축 로드맵 (정적 → 안정적 제품)
| 단계 | 상태 | 내용 |
|------|------|------|
| **0. 정적 + 로컬저장** | ✅ 현재 | React SPA + localStorage. 빠르고 무료, 단일 기기. |
| **0.5 서버리스 보강** | 🔨 진행 | Netlify Functions(노션 백업·PIN 검증). 키는 서버에만. |
| **1. 인증·계정** | ⬜ 계획 | 진짜 로그인(판매 고객용). 후보: 서버리스 + 관리형 인증. |
| **2. 데이터베이스** | ⬜ 계획 | 다기기 동기화·백업의 원천. 원생 데이터 안전 보관. |
| **3. 멀티테넌시** | ⬜ 계획 | 고객사(학원)별 분리된 데이터·설정. 판매 확장의 핵심. |
| **4. 운영 안정화** | ⬜ 계획 | 모니터링·에러 추적·자동 백업·롤백 가능한 배포. |

> 각 단계는 **수요가 확인된 만큼만** 올린다(린 스타트업: 과잉 선투자 금지). 판매 계약이 생기면 1→2로 당긴다.

## 6. 세부업무 (진행상황)
### 6-1. 현재 운영 자산 유지
- ✅ 완료 `[L1]` **도현컴퍼니 홈페이지 + 운영 대시보드** 구축·배포 (React+Vite+Tailwind, Netlify)
- ✅ 완료 `[L1]` **각 메뉴 직접 입력화 + 노션 백업 배관 + 보안 1차** (2026-09-11)
- ⬜ 대기 `[L0]` **배포 파이프라인 문서화** — 빌드·배포·롤백 절차 1장
- ⬜ 대기 `[L0]` **OSS 레지스트리** `docs/teams/homepage/oss_registry.md` 신설
### 6-2. 백엔드 준비
- ⬜ 대기 `[L0]` **인증·DB 후보 기술조사** → 대표 보고 (백엔드 1단계 착수 전)
- ⬜ 대기 `[L0]` **다기기 동기화 설계** (판매 계약 발생 시 우선순위 상승)
### 6-3. CS 체계
- ⬜ 대기 `[L0]` **장애 대응 절차(런북)** — 사이트 다운 시 순서
- ⬜ 대기 `[L0]` **고객 문의 채널·응대 템플릿** (판매 단계)

## 7. 다른 팀과의 협업
- **② 마케팅:** 홍보용 랜딩·홈페이지 요구사항을 받는다. (마케팅은 "무엇을", 홈팀은 "어떻게 만드나".)
- **⑤ 인프라:** 데이터 구조·대시보드 표준을 맞춘다.
- **⑦ 보안:** 배포·외부코드 도입 전 보안 신호등 판정을 받는다. (막지 않되, 안전하게.)
- **③ 수익화:** 판매용 제품 사양·가격에 기술 현실성을 입력한다.

## 8. 린 스타트업 정합성
- **컨시어지→제품:** 지금은 우리 학원용으로 직접 쓰며 검증. 팔릴 기능만 백엔드로 승격.
