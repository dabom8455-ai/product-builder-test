## 0. 준비물 (온보딩 폼에서 수령)
학원명 / 원하는 사이트명 / 수업 타임 / 수강료·결제일 / 입금계좌 / (선택) 원생 명단 / 노션 사용여부.

## 1. 사이트 생성 (테넌트 = 별도 사이트)
1. [ ] 동일 코드베이스(master)를 고객용 **새 Netlify 사이트**로 연결. (같은 repo → New site from Git, 또는 사이트 복제)
2. [ ] 사이트 이름/서브도메인 지정: 예) `학원명-dohyeon.netlify.app`.
3. [ ] 커스텀 도메인 원하면 연결(선택).

## 2. 환경변수 세팅 (고객별 고유값 — 격리의 핵심)
Netlify → Site settings → Environment variables:
- [ ] `DASHBOARD_PIN` = 고객 전용 PIN(신규 발급, 안전 채널로 전달)
- [ ] `NOTION_TOKEN` = 고객 노션 통합 토큰
- [ ] `NOTION_BACKUP_DB` = 고객 노션 백업 DB ID
> 🔒 Netlify Blobs 저장소는 **사이트 단위로 분리**되므로, 사이트를 나누면 홈페이지 콘텐츠·데이터가 고객 간 섞이지 않는다.

## 3. 배포·동작 확인
1. [ ] 배포 트리거 → 빌드 성공 확인.
2. [ ] `/dashboard` 접속 → PIN 잠금 동작 확인.
3. [ ] 자동화 3종 스모크 테스트: 상담 예약 1건(리마인드) · 진도 1건(월말 리포트 반영) · 입금 1건(미납 표시).
4. [ ] 노션 백업 1회 실행 → 고객 노션에 백업 생성 확인.

## 4. 고객 정보 반영
- [ ] 홈페이지/대시보드 기본 정보(상호·주소·전화·수업 타임)를 고객 확정본으로 입력.
- [ ] 원생 명단 이관(있으면) → 중복·오등록 검수.

## 5. 인계·기록

- [ ] 내부 웹 URL 레지스트리(`docs/infra/web_urls.md`)에 고객 인스턴스 1줄 기록.
- [ ] 성대리에게 인계(30일 체크인 예약), 보대리에게 지원 대상 등록.

## 🔴 코드에서 반드시 검증할 것 (셋대리 → ⑤ 인프라, 실물화 전 확인)
이 절차는 **설계 가설**이다. 실제 첫 세팅 전에 dohyeon-piano 코드로 아래를 확인해야 한다:
1. **환경변수만으로 테넌트가 실제 분리되는가** — DASHBOARD_PIN·NOTION_*가 코드에서 전부 env로 주입되는지(하드코딩 없음).
2. **Netlify Blobs가 사이트별로 격리되는가** — content.mjs가 사용하는 store가 사이트 스코프인지.
3. **동일 repo 다중 사이트 배포**가 충돌 없이 되는지(빌드·함수 배포).
4. 업데이트 배포 시 **고객 커스텀 값(상호·타임)이 덮이지 않는지** — 이 값들이 코드가 아니라 데이터/env에 있어야 함.

→ 위 4개가 OK면 **수동 복제로 즉시 판매 가능**. 하나라도 걸리면 그 부분만 코드 보완(⑤ 셋대리)이 선행. **완벽한 멀티테넌트는 고객 3~5명 시점까지 미룬다(견인 우선).**
