## 🟡 정직하게 공지할 제약 2가지 (성과보증·CS에 직결)
### 제약 A — 단일 브라우저 저장 (멀티기기 동기화 없음) ★중요
- 대시보드 데이터가 **그 브라우저에만** 저장됨. 원장이 **노트북+폰 두 기기**를 쓰면 데이터가 **동기화되지 않음**.
- 브라우저 데이터 삭제 시 손실 위험(노션 백업·내보내기로 복구하나 **수동 import** 필요).
- **대응(당장):** "한 기기(주로 쓰는 노트북)에서 사용 + 자동 백업 ON"을 온보딩에서 안내. 성과보증·CS 문서에 명시.
- **로드맵:** 서버 동기화(멀티테넌트 DB)는 고객 3~5명 시점 구축 과제(G7)와 함께.

### 제약 B — 고객 전용 '공개 홈페이지'는 아직 코드 편집 필요
- `site.ts` BRAND(상호·주소·전화)는 우리(도현컴퍼니) **판매 랜딩** 기준이라 고객용으로 쓰려면 소스 수정 필요 → 업데이트로 덮일 수 있음.
- **대응:** **첫 상품은 "운영 대시보드 중심"으로 판다.** 고객 공개 홈페이지는 옵션/후순위. (대시보드만으로 잡무 3종 해결 = 핵심 가치 충족)

## 결론 & 다음 수
- **판매 개시 가능:** 대시보드(원생·상담·진도·매출·입금 관리 + 노션 백업)를 수동 복제로 첫 고객에게 세팅 가능. 핵심 3기능 동작에 코드 장애물 없음.
- **선행 반영 3건:**
  1. 성과보증·CS·온보딩 문서에 **제약 A(단일 기기 + 자동백업)** 문구 추가.
  2. 제안서·계약서의 상품 범위를 **"운영 대시보드 중심"** 으로 명확화(공개홈은 옵션).
  3. (⑤ 셋대리 로드맵) 서버 동기화·멀티테넌트는 고객 3~5명 시점 착수.
