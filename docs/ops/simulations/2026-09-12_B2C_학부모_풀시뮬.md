# 🎭 실전 시뮬레이션 #1 — 학부모(B2C) 판매→운영→CS 풀 드라이런

> 지시: 대표(2026-09-12) — "실제 고객이 생겼다는 가정하에 판매-운영-CS 실제상황 연습."
> 형식: **클부장 풀 시뮬**(학부모·원장·시스템 1인 다역 자문자답) · 대표는 관전+피드백.
> 목적: 팔기/받기 전에 **전 과정을 손으로 굴려 막히는 지점(GAP)을 미리 잡는다**(컨시어지 MVP 리허설).
> 규칙: 확정 사실(주소·전화·예약제)만 사용 · 가격·타임 등 미확정은 `[원장 확정]` · 지어낸 후기·숫자 금지.
>
> **가상 고객:** 김○○ 어머니 / 자녀 초등 3학년 / 피아노 첫 입문 / 모현읍 거주 / 유입: 네이버 블로그 05호(진도강박) 읽고 문의.

범례: 🗣️=대사 · ⚙️=시스템/자동화 동작 · 📌=우리 자산 연결 · 🔴=GAP(미완성/결정 필요)

---

## 🎬 1막 — 판매 (문의 → 상담 → 등록 전환)

### S1. 인바운드 문의 (블로그 → 톡/전화)
🗣️ **학부모:** "안녕하세요, 블로그 글 보고 연락드려요. 초3 딸인데 피아노는 처음이에요. 상담 한번 받아볼 수 있을까요?"
⚙️ 문의 접수 → 대시보드 **원생/상담 파이프라인**에 '신규 리드' 자동 생성(이름·자녀 학년·유입경로=블로그05).
📌 유입경로 기록 = 콘텐츠 성과 로그와 연결(블로그가 실제 리드를 만들었는지 검증).
🔴 **GAP-1:** 문의를 *받는 단일 채널*이 아직 미확정(전화/네이버톡톡/폼 중 무엇?). → 대표 결정 필요.

### S2. 상담 예약 (예약제 안내)
🗣️ **원장:** "네 어머님, 반갑습니다 😊 상담은 원활한 수업을 위해 저녁 6시 이후 예약제로 진행해요. 이번 주 언제가 편하실까요?"
🗣️ **학부모:** "목요일 저녁 7시 괜찮아요."
⚙️ 대시보드 **일정 관리**에 상담 예약 등록 → 예약 확인 메시지 자동 발송(장소·주소·소요시간).
📌 주소 자동 삽입: 경기 용인 모현읍 왕산로14 몬테로이 2단지 상가 / ☎ 010-5158-3613.
🔴 **GAP-2:** 예약 확인·리마인드 메시지 **자동 발송이 실제 연결됐는지** 미검증(수동이면 원장 부담). → 자동화 상태 확인.

### S3. 상담 (니즈 파악 → 교육철학 → 제안)
🗣️ **원장:** "따님이 집에서 피아노에 관심 보이는 순간이 있었나요?"
🗣️ **학부모:** "유튜브 보고 따라 치려고 해요. 근데 저는 진도 빨리 나가는 것보다 제대로 배웠으면 좋겠어요."
🗣️ **원장:** "정확히 저희 방향이에요. 도현피아노는 '체르니 몇 번'보다 **박자·악보 읽기·기본기·표현**을 아이 수준에 맞춰 차근차근 봅니다. 처음엔 흥미와 기초를 같이 잡는 게 제일 중요해요."
📌 상담 스크립트 = 블로그 보이스 가이드(진도강박 편)와 동일 메시지 → **일관된 브랜드 경험**.
🗣️ **학부모:** "수업은 어떻게 되나요? 비용은요?"
🗣️ **원장:** "주 [원장 확정]회, 회당 [원장 확정]분이고, 수강료는 월 `[원장 확정]`원이에요. 남은 타임은 [원장 확정 요일/시간]이 있어요."
🔴 **GAP-3:** **수강료·수업 횟수·시간·남은 타임**이 미확정 → 판매의 핵심 정보가 빔. 대표가 표준값 확정 필요.

### S4. 등록 결정 (클로징)
🗣️ **학부모:** "그럼 목요일 그 타임으로 등록할게요."
⚙️ 대시보드 **등록 관리(contracts)**에 신규 계약 생성 → **원생 관리(customers)**로 승격 → 첫 수업일·준비물 안내 자동 발송.
⚙️ **입금 관리(deposits)**에 첫 달 수강료 청구 항목 생성 → 입금 확인 대기.
📌 상담→등록 전환 = 재무 KPI(재원 수·객단가)에 자동 반영.
🔴 **GAP-4:** 결제(계좌이체/카드/자동이체) 방식 미확정 → '입금 확인'을 원장이 수동으로 하는지, 자동 매칭인지 확인 필요.

**1막 산출:** 신규 리드 1 → 상담 예약 1 → 등록 1 (전환). 소요 자산: 상담 스크립트 ✅, 예약/등록/입금 대시보드 ✅(자동화 연결은 GAP-2,4).

## 🎬 2막 — 운영 (온보딩 → 수업 → 진도·결제 관리)

### S5. 첫 수업 온보딩
⚙️ 첫 수업 전날 **리마인드**(시간·준비물·주차 안내) 자동 발송.
🗣️ **원장(첫 수업 후):** "오늘 첫 시간엔 앉는 자세랑 손 모양부터 봤어요. 잘 따라와 줬어요 😊"
⚙️ **진도 관리**에 학생 카드 생성 → 오늘 진도(자세·손모양) 1행 기록.
🔴 **GAP-5:** 학부모에게 **진도·소식을 공유하는 채널·주기**가 정의됐는지(매주? 월말?) 미확정.

### S6. 월중 운영 (반복 루틴)
⚙️ 매 수업 진도 기록 → **월말 진도 리포트** 루틴(매월 25일)이 자동 초안 생성 → 원장 검토 → 학부모 발송.
⚙️ 결제일: **입금 관리**가 미입금 시 원장에게 알림 → 부드러운 안내 메시지.
📌 재무: 월 수강료 입금 → 매출·입금 대시보드 자동 반영 → 월말마감 루틴(매월 1일)에 집계.
🔴 **GAP-6:** '미입금 자동 알림'과 '월말 진도 리포트 자동 초안'이 **실제 배포·동작하는지** 검증 필요(기획만 있고 미구현일 수 있음).

**2막 산출:** 원생 1명 온보딩 완료, 진도·결제 루틴 진입. 병목은 대부분 "기획됨 vs 실제 동작" 확인.

## 🎬 3막 — CS (문의 → 트러블 → 이탈방지/리텐션)

### S7. 흔한 CS ① — 아이가 학원 가기 싫어해요
🗣️ **학부모:** "요즘 애가 피아노 가기 싫대요. 그만둬야 하나 고민이에요."
🗣️ **원장:** "충분히 그럴 수 있어요. 처음 몇 달은 흥미 곡선이 출렁여요. 다음 시간엔 아이가 좋아하는 곡 한 곡을 목표로 잡아볼게요. 2주만 같이 지켜봐 주실래요?"
📌 대응 스크립트(이탈 방어) = FAQ 자산으로 축적 → 다음 CS에 재사용.
🔴 **GAP-7:** **CS FAQ·이탈방어 스크립트 문서가 아직 없음**. → 클부장이 초안 작성 필요.

### S8. 흔한 CS ② — 결제·휴원·환불
🗣️ **학부모:** "다음 달에 2주 여행 가는데 수강료는 어떻게 되나요?"
🗣️ **원장:** "휴원·보강 규정은 [원장 확정: 예) 월 O회 보강 / 장기 휴원 시 처리]로 안내드려요."
🔴 **GAP-8:** **휴원·보강·환불 규정이 문서화 안 됨**. 매번 즉흥 대응 = 분쟁 위험. → 규정 1장 필요.

### S9. 리텐션 (재등록·추천)
⚙️ 3개월 시점 **만족도 체크인** 자동 안내 → 진도 리포트 + 발표회/이벤트 안내.
🗣️ **원장:** "따님 많이 늘었어요. 다음 달 미니 발표회 있는데 참여해볼까요? 😊"
📌 만족한 학부모 → **추천/후기** 요청(가짜 후기 금지, 실제 동의받은 것만) → 신규 리드 유입 = 선순환.
🔴 **GAP-9:** 만족도 체크인·발표회·추천 요청이 **루틴으로 자동화됐는지** 미확정.
