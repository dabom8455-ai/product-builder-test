# 🎭 실전 시뮬레이션 #1 (정정판) — 1인 원장에게 「자동화 패키지」 판매: 판매→세팅→유지보수

> 지시: 대표(2026-09-12). B2B 시스템 판매 시나리오 · 클부장 풀 시뮬(1인 다역) · 대표 관전+피드백.
> 목적: 파는·깔아주는·지켜주는 전 과정을 손으로 굴려 **막히는 지점(GAP)** 을 판매 전에 잡는다.
> 규칙: 확정 사실만 · 미확정은 `[대표 확정]` · 지어낸 후기·숫자 금지.
>
> **가상 고객:** 도현피아노 원장(첫 파일럿=우리 자신) / 1인 운영 / 잡무(상담·등록·진도·정산)에 치임 / 유입: 우리 블로그·유튜브 보고 **구글폼** 문의.
> **담당:** 판대리(판매)·셋대리(세팅)·보대리(유지보수)·성대리(고객성공) — `customer_journey_roles.md`.

범례: 🗣️대사 · ⚙️시스템 · 📌자산연결 · 🔴GAP

## 🎬 1막 — 판매 (구글폼 문의 → 진단 상담 → 제안 → 계약·결제)

### S1. 리드 유입 (콘텐츠 → 구글폼)
🗣️ **원장(고객):** [블로그/유튜브 보고 구글폼 제출] "1인 학원 운영하는데 상담·진도·정산이 너무 손이 많이 가요. 자동화 어떻게 시작하나요?"
⚙️ 구글폼 → 대시보드/노션 CRM에 **신규 리드** 생성(업종=피아노학원·규모=1인·유입=유튜브·고민=잡무과다).
📌 성과 로그(콘텐츠→리드) 연결로 어느 채널이 B2B 리드를 만드는지 검증.
🔴 **GAP-1:** 구글폼 → CRM **자동 연동**이 실제로 되나, 아니면 수기 옮김? → 확인/구축(⑤).

### S2. 판대리의 진단 상담 (문제와 사랑에 빠져라)
🗣️ **판대리:** "지금 하루 중 '가르치는 시간'말고 잡무에 몇 시간 쓰세요? 가장 스트레스 큰 잡무 3개만 꼽아주실래요?"
🗣️ **원장:** "상담 예약 왔다갔다, 매달 진도 정리해서 학부모 보내기, 입금 확인이요."
📌 린 캔버스식 문제 검증 — *솔루션이 아니라 문제*를 먼저 확정.
🔴 **GAP-2:** 표준 **진단 상담 스크립트/질문지**가 아직 없음 → 판대리용 문서 필요.

### S3. 마피아 제안 (거절 못 할 오퍼)
🗣️ **판대리:** "그 세 가지를 저희가 쓰는 시스템 그대로 깔아드립니다. **예약 자동화·월말 진도 리포트 자동 초안·입금 관리 대시보드.** 셋업 39만원에 저희가 직접 세팅·이관·교육까지 하고, 이후 호스팅·업데이트·지원은 월 `[대표 확정]`원이에요. 2주 안에 실제로 돌아가는 걸 보여드리고, 안 맞으면 [환불/보증 조건 대표 확정]."
📌 컨시어지 오퍼: "직접 써서 검증한 걸 그대로 깔아준다" = 최강 신뢰 근거.
🔴 **GAP-3:** **가격표(셋업+월구독)·보증/환불 조건**이 미확정 → 제안서가 빈다.
🔴 **GAP-4:** **제안서(1장)·계약서** 양식 없음 → 클로징 자산 필요.

### S4. 계약·결제
🗣️ **원장:** "좋아요. 진행할게요."
⚙️ 결제(셋업비 39만) → 영수증·계약 확정 → **온보딩 착수 티켓** 생성(셋대리에게 배정).
🔴 **GAP-5:** **결제 수단**(Gumroad/계좌/카드) 및 세금계산서 발행 흐름 미확정(재팀장).

**1막 산출:** 리드1→상담1→계약1. 병목: 진단 스크립트·가격·제안/계약서·결제 흐름(대부분 자산 부재).

## 🎬 2막 — 온보딩·세팅 (셋대리: 결제 후 → 돌아가는 시스템 인계)

### S5. 온보딩 폼 (고객 정보 수집)
⚙️ 셋대리 → 고객에게 **온보딩 폼** 발송: 학원명·원장 연락처·수업 요일/타임·현재 원생 명단(선택)·수강료·계좌.
🔴 **GAP-6:** **온보딩 체크리스트/폼**(무엇을 받나) 표준 문서 없음.

### S6. 워크스페이스 세팅 (핵심 작업)
⚙️ 셋대리 작업 순서:
1. 고객 전용 **대시보드 인스턴스** 생성(홈페이지 하위/서브도메인) + **DASHBOARD_PIN** 발급.
2. 대시보드 메뉴 활성화(원생·상담·일정·진도·매출·입금).
3. **자동화 루틴 ON**: 상담 예약 리마인드 / 월말 진도 리포트 초안 / 미입금 알림.
4. **노션 백업 연결**(고객 노션 토큰) — 우리가 겪은 그 과정(env 3종).
5. 기존 원생 데이터 이관(있으면).
🔴 **GAP-7 (최대 병목):** 지금 대시보드는 **단일 테넌트(우리 것 하나)**. 고객별 **복제·데이터 격리·프로비저닝**이 아직 구조화 안 됨. → ⑤ 인프라 아키텍처 결정 필요(수동 복제로 시작 vs 멀티테넌트 구축).

### S7. 인수 교육·확인 (Go-live)
🗣️ **셋대리:** "원장님, 상담 예약 한 건 직접 넣어보실래요? 리마인드 자동으로 가는 것 보이시죠. 월말이면 진도 리포트 초안이 여기 뜹니다."
⚙️ 고객 **인수확인 체크**(각 기능 1회 성공) → '납품 완료' → 성대리에게 인계.
🔴 **GAP-8:** **사용법 교육 자료**(짧은 가이드/영상) 없음.

**2막 산출:** 고객 시스템 Go-live. 최대 병목 = 멀티테넌트/프로비저닝(G7).

## 🎬 3막 — 유지보수·기술지원·고객성공 (보대리·성대리)

### S8. 기술 지원 (보대리)
🗣️ **원장:** "대시보드에서 입금 관리가 안 열려요."
⚙️ 보대리 → 지원 티켓 접수 → 재현 → 배포/수정 → 회신. **SLA**(예: 영업일 1일 내 1차 회신) 적용.
🔴 **GAP-9:** **지원 채널·SLA·티켓 관리**가 정의 안 됨.

### S9. 유지보수·업데이트 (보대리)
⚙️ 우리 홈페이지 업데이트(master→Netlify 자동 배포)가 **고객 인스턴스에도 안전히 반영되나?** 회귀 위험 관리.
🔴 **GAP-10:** 다고객 환경에서 **업데이트 배포·롤백 정책** 없음(G7과 직결).

### S10. 고객성공·리텐션 (성대리)
⚙️ 30일 시점 **체크인**: "잡무 시간 얼마나 줄었어요?"(가치 실현 확인) → 활용 낮은 기능 재교육.
🗣️ **성대리:** "블로그 자동 초안 기능도 켜드릴까요?"(업셀) / 만족 시 **추천·후기** 요청(동의받은 것만).
📌 만족 고객 → 사례/추천 → 신규 B2B 리드 = 선순환(荊州 확장).
🔴 **GAP-11:** 체크인·업셀·해지방어 **리텐션 루틴** 없음.
