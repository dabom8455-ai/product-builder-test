# 카페댐 메뉴별 기능 기획 (v2)

> 2026-10-07 · MVP(v1) 위에 더하는 기능. 기준: **입력은 늘리지 않고, 이미 쌓인 데이터로 판단을 돕는다.**
> 각 기능은 "누가 · 언제 · 무엇을 결정하는가"로 정의하고, 새로 입력받는 데이터는 표의 **입력** 칸에 적었다.

## 데이터 흐름에서 v2가 채우는 빈칸

| 빈칸 | v1의 한계 | v2 기능 |
|---|---|---|
| 실제 원가 | 레시피 원가(이론값)만 안다. 버리는 양·과다 사용은 보이지 않는다 | 재료 매입 기록 → **이론 사용량 vs 실제 매입량** 비교 |
| 인건비 계획 | 일이 끝난 뒤 급여만 계산한다 | 주간 근무표 → **예상 인건비, 지각·결근 자동 표시** |
| 매출 맥락 | 숫자만 쌓인다 | 날짜별 메모(날씨·이벤트), 휴무일, 월 목표 |
| 의사결정 전 시뮬레이션 | 메뉴 1개 가격만 바꿔 볼 수 있다 | 손익 시나리오(가격·판매량·인건비·고정비 동시 변경) |

---

## 1. 홈 — "오늘 무엇을 해야 하나"

| 기능 | 설명 | 입력 |
|---|---|---|
| 오늘 할 일 | 데이터에서 자동 생성되는 체크리스트: 어제 마감 미입력, 답글 대기 부정 리뷰, 퇴근 미기록, 보건증 만료 30일 이내, 원가율 초과 메뉴, 오늘 근무 예정자. 각 항목은 해당 화면으로 바로 이동 | 없음 |
| 월 목표 진행률 | 월 매출 목표 대비 누적 매출, 남은 영업일 기준 하루 필요 매출 | 설정의 월 목표 |
| 주간 비교 | 이번 주(월~어제)와 지난주 같은 요일까지의 매출 비교 | 없음 |

## 2. 메뉴·원가 — "실제로 재료가 얼마나 새고 있나"

| 기능 | 설명 | 입력 |
|---|---|---|
| 재료 매입 기록 | 영수증 한 장 = 매입 1건(날짜, 재료 여러 개 × 수량 × 단가). 저장하면 재료 단가가 자동 갱신되고 단가 이력이 남는다 | 매입 영수증 |
| 로스 분석 | 월별로 레시피 기준 **이론 사용량**(판매수량 × 레시피, 서브레시피 전개)과 **실제 매입량**을 재료별로 비교. 차이가 큰 재료부터 표시 | 없음 (매입 기록 활용) |
| 메뉴 복제 | 사이즈·HOT/ICE 변형 메뉴를 레시피째 복사 | 없음 |

> 로스 = 매입 − 이론 사용량. 재고 변동(월초·월말 재고 차이)은 반영하지 않으므로 2~3개월 추세로 본다.

## 3. 매출 입력 — "빠뜨린 날 없이, 맥락과 함께"

| 기능 | 설명 | 입력 |
|---|---|---|
| 매출 달력 | 월 달력에 일매출 표시. 미입력일·휴무일 구분, 날짜를 누르면 그날 마감 입력으로 이동 | 없음 |
| 지난주 같은 요일 불러오기 | 마감 입력 시 지난주 같은 요일 수량을 채워 넣고 수정만 하게 한다 | 없음 |
| 날짜 메모 | 날씨(맑음·흐림·비·눈·폭염·한파)와 메모(이벤트, 공사 등). 달력·손익에서 함께 보인다 | 선택 입력 |

## 4. 손익 — "이 결정을 하면 얼마가 남나"

| 기능 | 설명 | 입력 |
|---|---|---|
| 6개월 추이 | 월별 매출·순수익 막대 + 순이익률 | 없음 |
| 손익 시나리오 | 기준 월 손익에 가격 ±%, 판매량 ±%, 인건비 ±원, 고정비 ±원을 동시에 적용해 순수익 변화 계산 | 슬라이더 |
| 영업일 기준 손익분기 | 휴무 요일을 빼고 하루 필요 매출 계산 | 설정의 휴무 요일 |
| 매입 vs 이론원가 | 그 달 실제 매입액과 레시피 원가 합계 비교 | 없음 |

## 5. 메뉴 분석 — "언제, 어디서 팔리나"

| 기능 | 설명 | 입력 |
|---|---|---|
| 요일별 히트맵 | 메뉴 × 요일 평균 판매량. 요일 한정 메뉴·재료 준비량 판단 | 없음 |
| 채널별 인기 순위 | 홀과 배달 채널의 Top 5 메뉴를 나란히 비교 | 없음 |

## 6. 리뷰 답글 — "여러 개를 한 번에"

| 기능 | 설명 | 입력 |
|---|---|---|
| 여러 리뷰 한꺼번에 붙여넣기 | 빈 줄로 구분된 리뷰를 한 번에 등록. ★ 개수나 "4점" 표기가 있으면 별점 자동 인식 | 붙여넣기 |
| 일괄 초안 | 답글 대기 리뷰 전체의 초안을 한 번에 생성 (부정 리뷰는 확인 필요 표시 유지) | 없음 |
| 맺음 서명 | 모든 답글 끝에 붙는 가게 서명(예: "— 카페 댐 사장 드림") | 설정 |
| 월별 별점 추이 | 최근 6개월 평균 별점·리뷰 수 | 없음 |

## 7. 알바 근태 — "일하기 전에 계획하고, 계획과 비교"

| 기능 | 설명 | 입력 |
|---|---|---|
| 주간 근무표 | 주 단위로 직원별 근무 시간 배치. 지난주 근무표 복사 | 근무 계획 |
| 계획 vs 실제 | 근무표와 출퇴근 기록을 비교해 지각(5분 초과)·조퇴·결근 자동 표시 | 없음 |
| 예상 인건비 | 근무표 기준 이번 주·이번 달 예상 급여(주휴수당 포함)와 주 15시간 경계 경고 | 없음 |

## 8. 홍보 포스터 — "올릴 글까지 한 번에"

| 기능 | 설명 | 입력 |
|---|---|---|
| 할인가 표시 | 할인 이벤트일 때 정가 취소선 + 할인가 | 할인가 |
| 인스타 캡션 | 포스터 문구·메뉴·가격·리뷰 칭찬 키워드로 게시글 본문과 해시태그 생성(AI, 없으면 템플릿), 복사 버튼 | 없음 |

## 9. 설정

| 기능 | 설명 |
|---|---|
| 휴무 요일 | 손익분기·목표 계산과 매출 달력에 반영 |
| 월 매출 목표 | 홈 진행률 |
| 답글 서명 | 리뷰 답글 맺음말 |

## 데이터 모델 추가

```
Purchase  (id, date, items: [{ingredientId, packs, packPrice}], memo)
Shift     (id, employeeId, date, start, end)          -- 근무 계획
DayNote   (id=date, date, weather, memo)
Store     + monthlySalesTarget, closedDays[], replySignature
```

클라우드 저장: `purchases`·`dayNotes` 는 문서 1개, `shifts` 는 판매·근태처럼 월별 문서로 나눈다.

## 구현 순서

1. 도메인 로직 + 단위 테스트: 이론 사용량·로스, 계획 vs 실제, 예상 인건비, 시나리오, 요일 히트맵, 리뷰 일괄 파싱
2. 데이터 모델·저장(어댑터)·샘플 데이터
3. 화면: 설정 → 매출 → 메뉴·원가 → 근태 → 손익 → 분석 → 리뷰 → 포스터 → 홈
4. 검증: 타입·린트·테스트·빌드, 브라우저 점검, 아티팩트 재배포
