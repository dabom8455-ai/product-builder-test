# 조직 구조 & 클부장 운영체계

이 문서는 **누가 무엇을 책임지는가**, 그리고 **총괄책임자(클부장)가
병렬 조직을 어떻게 굴리고 보고하는가**를 정의한다.

---

## 1. 조직 원칙: 병렬 조직

4개 팀은 서로를 기다리지 않고 **동시에** 움직인다.
단, 팀들이 따로 놀지 않도록 클부장이 **연결·조정·우선순위**를 잡는다.
그리고 4개 팀이 딛고 서는 바닥으로 **⑤ 시스템·데이터 인프라**를 클부장이 직접 관장한다.

```
대표(원장) ── 방향/최종결정
   │   └╌╌ 로비서 (대표 직속 비서 · 매일 07:00 데일리 브리핑 · 인사이트 정리)
   │
클부장(COO) ── 조정 · 진행점검 · 우선순위 · 보고
   │   ├╌╌ ⑤ 시스템·데이터 인프라 (직속 · 모든 과정을 데이터로)
   │   ├╌╌ ⑥ 전략기획실 (직속 · 경쟁·시장 빈틈 탐색)
   │   └╌╌ ⑦ 보안팀 · 보팀장 (직속 · 정보·시스템·법적 안정성 / 속도 저해 금지)
   ├── ① 학원운영팀장
   ├── ② 마케팅팀장
   ├── ③ 수익화팀장
   ├── ④ 전자책·글쓰기팀장
   └── ⑧ 홈페이지 구축·유지보수(CS)팀장 (홈팀장)
```

- **대표:** 방향 제시, 자원 배분 최종 결정, 헌장 수호.
- **클부장:** 대표 방향을 4개 팀 실행으로 번역. 팀 간 충돌 조정. 매주 보고. **⑤ 인프라 직접 관장.**
- **팀장:** 각 팀 목표 달성 책임. 세부업무를 직원(또는 자동화 에이전트)에게 분배.
- **⑤ 시스템·데이터 인프라(직속):** 4개 팀의 모든 활동을 데이터로 기록·표준화하는 바닥. 사람 손을 넘어서면 정식 팀으로 승격. → [`docs/teams/team5_data_infra.md`](teams/team5_data_infra.md)

## 2. 각 팀 한 줄 정의 & 팀 간 인터페이스

| 팀 | 팀장 | 한 줄 임무 | 다른 팀에 넘기는 것 (Output) |
|----|------|-----------|------------------------------|
| ① 학원운영팀 | 학팀장 | 학원 운영을 자동화해 원장 시간을 산다 | 운영 데이터·상담 노하우 → ③④ |
| ② 마케팅팀 | 마팀장 | 시스템/학원을 알리고 판다 | 고객 리드·시장 피드백 → ③, 대표 |
| ③ 수익화팀 | 수팀장 | 재무를 설계해 수익을 극대화한다 | 가격·수익모델 → ①②④ |
| ④ 전자책·글쓰기팀 | 전팀장 | 노하우를 지식상품으로 만든다 | 콘텐츠 자산 → ② (마케팅 소재) |
| ⑧ 홈페이지 구축·유지보수(CS)팀 | 홈팀장 | 모든 홈페이지의 구조설계·생성·관리·수리를 책임진다 | 배포된 사이트·기능·백엔드 → 전사·고객 · [`docs/teams/team8_homepage_cs.md`](teams/team8_homepage_cs.md) |
| ⑤ 시스템·데이터 인프라 *(직속)* | (클부장 직속) | 모든 과정을 데이터로 남긴다 | 데이터·대시보드 → 전 팀·대표 |
| ⑥ 전략기획실 *(직속)* | (클부장 직속) | 경쟁·시장을 분석해 빈틈을 찾는다 | 경쟁 인텔·빈틈 리포트 → 전 팀·대표 |
| ⑦ 보안팀 *(직속)* | 보팀장 | 정보·시스템·법적 안정성을 지키되 **속도를 막지 않는다** | 보안 신호등·체크리스트·인시던트 리포트 → 전 팀·대표 · [`docs/teams/team7_security.md`](teams/team7_security.md) |
| 🤖 로비서 *(대표 직속)* | (대표 직속 AI 비서) | 대표의 하루를 설계하고 배움을 자산으로 남긴다 | 데일리 브리핑·인사이트 노트 → 대표 · [`docs/roles/rovisor.md`](roles/rovisor.md) |

> 팀장은 각 팀을 **조사→검토→기획→제안→실행**으로 굴리고, **모든 진행을 클부장에게 빠짐없이 보고**한다.
> 상세 규약: [`docs/teams/00_team_operating_guidelines.md`](teams/00_team_operating_guidelines.md)

> **핵심 연결고리:** ①에서 나온 실제 운영 노하우가 ④의 전자책이 되고,
> ④의 콘텐츠가 ②의 마케팅 소재가 되고, ③이 전 과정의 가격을 매긴다.
> 한 바퀴가 곧 선순환이다.

## 3. 클부장 운영체계 (총괄책임자는 매주 이 5가지를 한다)

### (1) 진행상태 점검 — 신호등
매주 각 팀의 상태를 3색으로 판정한다.

| 신호 | 의미 | 클부장 조치 |
|------|------|-------------|
| 🟢 Green | 계획대로 진행 | 유지, 다음 마일스톤 확인 |
| 🟡 Yellow | 지연/위험 신호 | 원인 파악, 자원 재배치 검토 |
| 🔴 Red | 막힘/중단 | 즉시 개입, 대표 보고, 우선순위 조정 |

### (2) 미흡사항 & 우선조치 판단 — 우선순위 매트릭스
무엇을 먼저 할지는 **영향도 × 시급성**으로 자른다.

```
        시급성 높음        시급성 낮음
영향 큼  [즉시 실행]        [계획 편성]
영향 작음 [빠르게 위임]      [나중에/버림]
```

- 2026 목표(MVP 출시)에 가까운 일 = 영향 큼.
- "이번 주 안 하면 물길이 막히는 일" = 시급성 높음.

### (3) 병렬 조정 — 자원·의존성 관리
- 팀 간 **의존성**(A팀 산출물이 B팀 입력)을 추적해 병목을 없앤다.
- 한 팀에 일이 몰리면 우선순위를 재배치한다.
- 중복 작업(두 팀이 같은 걸 만듦)을 발견하면 통합한다.

### (4) 대표 보고 — 매주 1회
[`docs/templates/weekly_report.md`](templates/weekly_report.md) 양식으로 보고.
핵심만: **이번 주 진척 / 위험(Red·Yellow) / 대표 결정 필요 사항 / 다음 주 초점.**

### (5) 자동화 판정
모든 반복 업무에 대해 자동화 단계를 매긴다.
**수동(L0) → 반자동(L1) → 완전자동(L2).**
L2에 도달하고 검증된 모듈은 **판매 상품 후보**로 ③수익화팀·②마케팅팀에 넘긴다.

## 4. RACI (누가 책임지는가)

R=실행, A=최종책임, C=협의, I=보고받음

| 활동 | 대표 | 클부장 | 팀장 |
|------|------|--------|------|
| 회사 방향/비전 확정 | **A/R** | C | I |
| 팀별 목표 수립 | A | **R** | C |
| 세부업무 실행 | I | A | **R** |
| 팀 간 우선순위 조정 | I | **A/R** | C |
| 자동화 상품화 결정 | **A** | R | C |
| 데이터 표준·인프라 관리 (⑤) | I | **A/R** | C |
| 보안 판정·개인정보·컴플라이언스 (⑦) | I(중대건 A) | **A/R** | C(보팀장 R) |
| 홈페이지 구축·배포 (⑧) | I | **A** | **R**(홈팀장) |
| 외부코드(OSS) 도입 결정 (⑧) | **A**(승인) | R | C(홈팀장 제안) |
| 주간 보고 | I | **R** | C |

## 5. 업무 상태 관리 규약 (모든 팀 공통)

각 팀 문서의 세부업무는 아래 상태 태그로 관리한다.

- `⬜ 대기` — 아직 시작 안 함
- `🔨 진행` — 작업 중
- `✅ 완료` — 끝남 (검증 포함)
- `⛔ 막힘` — 블로커 있음 (클부장 개입 대상)

자동화 단계는 함께 표기한다: `[L0]` 수동 / `[L1]` 반자동 / `[L2]` 완전자동.
