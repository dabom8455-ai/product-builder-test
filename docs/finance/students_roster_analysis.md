# 원생 명단 분석 — 9월 출석부 기반

> 출처: 도현피아노 9월 출석부(원장 제공, 2026-09-09). 분석·데이터화: ⑤ 인프라 + ③ 수익화.
> **개인정보 최소화:** 원생(미성년) 실명 등 개별 데이터는 **노션 「원생 명단(Students)」 DB에만** 저장하고, 본 저장소 문서에는 집계·방법론만 남긴다.
> 노션 DB: 「원생 명단 (Students) — 9월 출석부 기반」 (① 학원운영팀 페이지 하위)

---

## 1. 집계
- **출석부 등재 원생: 28명** (순번 No.1~28).
- 개별 레코드 28건을 노션 DB에 생성(이름·No·과정·반빈도·원비수납메모·비고).
- 현재 각 원생의 **과정·반빈도 = "확인필요"** 로 세팅(아래 판독 한계 때문). 원장 확인 후 확정.

## 2. 판독 한계 (정직하게)
필기 출석부 **사진 1장**에서 나온 것이라 다음은 신뢰도가 낮다 → **원장 검증 필수**:
- **개별 출석 횟수·반·빈도:** 슬래시 표기가 겹쳐 사진만으론 정확 카운트 불가 → DB에 '확인필요'로 두고 원장이 채운다.
- ~~이름 판독 불확실 6건~~ → **원장 확인 완료(2026-09-09):** No.5 윤다솜 · 7 채원 · 14 범서원 · 15 준우 · 22 상윤 · 25 다온 (7·15·22·25는 성 없이 기재).
- **원비수납칸 요일 메모:** No.2·6·10에 요일 표기 흔적(판독 일부 불명) — 결제일인지 수업요일인지 확인 필요.

## 3. 관찰 인사이트
- **형제(가족 단위) 추정 4쌍:** (6·7)(14·15)(21·22)(24·25) — 위 행과 성을 공유하는 들여쓰기 패턴. 사실이면 **가족 등록/형제 할인·추천** 마케팅 레버.
- **정원 대비:** 반별 정원 9명. 28명 = 여러 반 운영 중.

## 4. 재무 연결 (③ 수익화)
- **원생 수 갱신:** 기존 추정 24명 → **출석부 등재 28명**(활동 원생 확정은 원장 확인 필요).
- 반·빈도 분포가 확정되면 → 가격표(`tuition_pricing.md`)와 곱해 **평균 객단가·월 매출·손익분기**를 정밀 재계산.
- **원장 액션(5분):** 노션 DB에서 각 원생의 **과정(기초/중급/고급/입시/칼림바)** 과 **반빈도(주2/3/5)** 만 선택 → 즉시 계산 들어감. 겸사겸사 판독 불확실 이름 6건도 확인.

## 4-1. 명단 관리 규칙 (2026-09-09 대표 지시 · ① 학원운영)
- 노션 「원생 명단」에 **순번(No)·최초등록일·재원상태(재원/휴원/이탈)** 관리.
- **이탈해도 삭제 금지** → 재원상태=이탈로 표시(이력 보존).
- **매월 원생 현황 스냅샷**을 남긴다 → [`docs/mvp/roster_monthly_snapshot.md`](roster_monthly_snapshot.md) (2026-09 = 28명 베이스라인). 25일 루틴이 함께 갱신.

## 5. 상품화 힌트
- 이 "출석부 → 자동 데이터화 → 재무 연결" 흐름 자체가 ①운영자동화 + ③재무설계 자동화의 **판매 모듈 시나리오**다. 우리 학원에서 검증 후 상품으로.
