# 데이터 레지스트리 (Data Registry)

> ⑤ 시스템·데이터 인프라의 핵심 문서. **"우리 데이터가 어디 사는가"**를 한 곳에 기록한다.
> **모든 노션 DB는 여기 등록되어야 한다.** 등록되지 않은 DB는 "존재하지 않는 것"으로 간주. (중복 방지의 근거)

관리: 클부장 직속(⑤) · 워크스페이스: 이수한의 노션 · 최종 갱신: 2026-09-11 (조직진단 반영)

---

## 🔒 데이터 거버넌스 규칙 (중복 방지)
1. **도메인당 DB 1개.** 같은 목적의 DB를 두 개 만들지 않는다. 새 DB가 필요하면 **먼저 이 레지스트리에서 기존 DB를 확인**한다.
2. **DB 신설은 ⑤ 등록 의무.** 어느 팀이든 노션 DB를 새로 만들면 **즉시 이 표에 한 줄 추가**(이름·data_source_id·주관팀·정본여부). 등록 없는 DB 생성 금지.
3. **SSOT(단일 진실).** 같은 정보를 두 DB에 따로 적지 않는다. 한 DB가 **정본(master)**, 나머지는 **파생(집계·이력·리포트)**으로 서로 참조만 한다.
4. **원생 데이터의 정본은 「원생 명단」 하나.** 월별 현황·진도 리포트는 여기서 파생된 집계/이력이다.

## 입력 규칙 (표준)
- **날짜:** `YYYY-MM-DD` · **상태값:** 정해진 선택지만(임의 추가 금지, ⑤ 승인 후 옵션 추가)
- **한 건 = 한 줄** · **리드 → 상담 연결 필수**(전환율 근거)
- **원생 데이터는 「원생 명단」에만 입력** → 월별 현황·진도 리포트는 참조/집계로 파생
