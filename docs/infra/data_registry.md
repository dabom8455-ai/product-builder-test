# 데이터 레지스트리 (Data Registry)

> ⑤ 시스템·데이터 인프라의 핵심 문서. **"우리 데이터가 어디 사는가"**를 한 곳에 기록한다.
> 저장소(노션 DB)가 추가·변경될 때마다 여기를 갱신한다. (⑫ 도메인의 시작)

관리: 클부장 직속 · 워크스페이스: 이수한의 노션

## 스키마 요약

### ① 리드 (Lead)
`리드명`(제목) · `유입경로`(전화/문자/카카오/네이버/인스타/워크인/홈페이지폼/기타) · `연락처` · `아이나이` · `문의내용` · `유입일` · `상태`(신규/상담예약/상담완료/등록/보류/이탈) · `담당` · `비고`

### ② 상담 (Consultation)
`상담건`(제목) · `리드`(→① 리드 양방향 연결) · `상담일시` · `방식`(방문/전화/온라인) · `결과`(등록/보류/이탈/재상담) · `담당` · `메모`

### ⑪ 의사결정 로그 (Decision Log)
`안건`(제목) · `날짜` · `결정` · `근거` · `결과_후속` · `관련영역`(조직/마케팅/운영/수익화/전자책/인프라/제품) · `결정자`

---

## 연결 구조 (관계)

```
① 리드  ──(1:N)──▶  ② 상담     : 리드 1건이 여러 번 상담될 수 있음
⑪ 의사결정 로그              : 독립 (회사 전체 결정 기록)
```

---

## 입력 규칙 (표준)

- **날짜:** `YYYY-MM-DD` (예: 2026-09-08)
- **상태값:** 위 스키마의 정해진 선택지만 사용 (임의 추가 금지 — 필요 시 클부장 승인 후 옵션 추가)
- **한 건 = 한 줄:** 문의 1건, 상담 1건, 결정 1건마다 새 레코드
- **리드 → 상담 연결:** 상담 기록 시 반드시 해당 리드를 연결 (전환율 집계의 근거)
