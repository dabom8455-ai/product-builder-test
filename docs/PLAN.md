# 카페 운영 올인원 앱 기획서 (가칭: **카페댐 CafeDam**)

> 버전 0.1 · 2026-10-06
> 목적: 1인~소규모 카페 사장님이 **리뷰 · 원가 · 근태 · 홍보 · 손익 · 메뉴 전략**을 하나의 앱에서 처리하도록 한다.

---

## 0. 한 줄 정의 & 설계 원칙

**"매출 데이터가 상류에서 한 번 들어오면, 하류의 모든 의사결정이 자동으로 흐르는 카페 운영 시스템."**

6개 기능을 따로 만들면 사장님은 6번 입력해야 합니다. 이 앱은 **입력 지점을 상류 3곳으로 최소화**하고, 나머지 기능은 그 데이터를 재사용하도록 설계합니다.

```
                ┌─────────────── 상류 (입력) ───────────────┐
                │  ① 재료·레시피   ② 판매(POS/배달)   ③ 출퇴근  │
                └──────┬──────────────┬──────────────┬──────┘
                       ▼              ▼              ▼
                 [원가 계산]    [매출 집계]     [인건비 계산]
                       │              │              │
                       └──────┬───────┴──────────────┘
                              ▼
                       [순수익 계산]  ──►  [메뉴 분석 & 조정 제안]
                                                   │
                     [리뷰 자동 댓글] ◄── 메뉴/리뷰 키워드 ──┤
                                                   ▼
                                           [홍보 포스터 제작]
```

| 원칙 | 의미 |
|---|---|
| 한 번 입력, 여러 번 사용 | 레시피 1회 등록 → 원가·마진·메뉴분석·포스터 가격표 모두 자동 반영 |
| 자동화는 "초안 + 1탭 승인" | 리뷰 답글·포스터·메뉴 조정은 AI가 초안, 사장님은 승인만 |
| 숫자는 항상 근거 표시 | 순이익·원가율 옆에 계산식을 펼쳐 볼 수 있게 |
| 모바일 우선 | 카운터 뒤에서 한 손으로 쓰는 앱 |

## 1. 타깃 사용자 & 문제 정의

| 페르소나 | 상황 | 현재 고통 |
|---|---|---|
| **사장님 A (1인 카페, 30대)** | 직접 음료 제조 + 배달 병행 | 리뷰 답글 밀림, 원가를 감으로 책정 |
| **사장님 B (알바 3~6명 운영)** | 홀 + 배민 + 네이버 예약 | 엑셀 근태·주휴수당 계산 실수, 월말 정산 스트레스 |
| **알바생 C** | 주 15~25시간 근무 | 출퇴근 기록 분쟁, 급여 명세 불투명 |

**핵심 문제**: 카페 사장님은 "장사는 잘 되는 것 같은데 남는 게 없다"를 숫자로 확인하지 못한다.

## 2. 기능 명세

### 2.1 리뷰 자동 댓글 (네이버 · 배민)

**목표**: 리뷰 답글 작성 시간을 리뷰당 3분 → 10초로.

| 항목 | 내용 |
|---|---|
| 수집 | 네이버 스마트플레이스 / 배민 사장님광장 리뷰 수집 |
| 분석 | 별점, 감정(긍정/중립/부정), 언급 메뉴, 키워드(맛·양·포장·배달시간·친절) 추출 |
| 생성 | LLM으로 답글 초안 생성 — 가게 말투 프리셋(친근/정중/위트) + 언급 메뉴 반영 + 반복 문구 회피 |
| 승인 | 긍정 리뷰: 자동 게시 옵션 / **부정 리뷰(별점 ≤3): 반드시 사장님 확인 후 게시** |
| 피드백 | 부정 키워드가 특정 메뉴에 반복되면 → 메뉴 분석(2.6)에 경고 신호 전달 |

**⚠️ 현실 제약 (중요)**
- 네이버 스마트플레이스·배민 사장님광장 모두 **리뷰 답글 작성용 공식 공개 API가 없습니다.**
- 따라서 단계적으로 접근합니다.
  1. **MVP**: 리뷰 텍스트를 붙여넣기/공유하기 → AI 답글 생성 → 복사 버튼 (약관 리스크 0)
  2. **V2**: 사장님 본인 계정으로 동작하는 브라우저 확장/자동화로 리뷰 수집·게시 보조 (각 플랫폼 이용약관 검토 필수, 사장님 로그인 정보는 서버 저장 금지)
  3. **V3**: 공식 파트너 API 제휴 또는 리뷰 관리 대행 솔루션과 연동

**답글 생성 프롬프트 설계 요소**: 가게명, 말투 프리셋, 리뷰 원문, 별점, 언급 메뉴, 최근 답글 5개(중복 회피), 금지어(할인 약속·환불 확정 등 사장님 승인 필요 표현).

### 2.2 음료·디저트 원가 계산 툴

**목표**: 모든 메뉴의 원가율을 실시간으로 안다.

**데이터 구조**
```
재료(Ingredient)  : 원두 1kg = 28,000원, 우유 1L = 2,600원, 컵 12oz = 85원 ...
  └ 단위원가 자동 계산: 원두 1g = 28원, 우유 1ml = 2.6원
레시피(Recipe)    : 카페라떼 = 원두 18g + 우유 200ml + 컵 1 + 뚜껑 1 + 빨대 1
  └ 메뉴 원가 = Σ(재료 사용량 × 단위원가) + 로스율 보정
```

| 기능 | 설명 |
|---|---|
| 재료 단가 관리 | 매입 영수증 입력 시 단가 갱신, 단가 변동 이력 그래프 |
| 레시피 빌더 | 메뉴별 재료·용량 등록, HOT/ICE·사이즈 옵션별 레시피 분기 |
| 반제품(서브레시피) | 바닐라시럽·크림·베이스처럼 직접 만드는 재료를 레시피로 등록해 재사용 |
| 원가율 계산 | 원가 / 판매가 × 100. 매장가와 **배달가(수수료·포장재 포함)** 각각 계산 |
| 가격 시뮬레이터 | "목표 원가율 30%면 판매가는?" / "우유값 10% 오르면 마진 영향은?" |
| 경고 | 원가율이 목표치(기본: 음료 30%, 디저트 35%) 초과 시 알림 |

**배달 실질 마진 공식**
```
배달 순마진 = 배달판매가 − 메뉴원가 − 배달포장재 − 플랫폼중개수수료 − 결제수수료 − 배달비 부담분 − 부가세
```

### 2.3 알바 근태관리 툴

**목표**: 출퇴근 분쟁 0, 급여 계산 자동화, 노무 리스크 사전 경고.

| 기능 | 설명 |
|---|---|
| 출퇴근 체크 | 알바 앱에서 **매장 Wi-Fi(SSID) 또는 GPS 반경 50m** 확인 후 체크, 매장 태블릿 QR 대안 |
| 스케줄 | 주간 근무표 작성·공유, 대타 요청/승인 |
| 급여 자동 계산 | 시급 × 실근무시간 + 주휴수당 + (해당 시) 연장·야간·휴일 가산 |
| 휴게시간 | 4시간 근무 시 30분, 8시간 시 1시간 휴게 자동 반영 |
| 급여명세서 | 월별 명세서 PDF/카톡 발송 (임금명세서 교부 의무 대응) |
| 노무 경고 | 최저임금 미달, 주 15시간 경계 근접, 근로계약서 미작성, 보건증 만료 알림 |

**계산 규칙 (설정값으로 관리, 매년 갱신)**
| 규칙 | 2026년 기준 |
|---|---|
| 최저시급 | 10,320원 |
| 주휴수당 | 주 소정근로 15시간 이상 & 개근 시, (주 소정근로시간 ÷ 40) × 8 × 시급 (최대 8시간분) |
| 연장·야간(22~06시)·휴일 가산 50% | **상시 5인 이상 사업장만 적용** → 매장 설정에서 사업장 규모 입력 |
| 4대보험/3.3% | 고용형태별 공제 선택 |

> 법 규정은 변경될 수 있으므로 규칙 테이블은 코드가 아닌 **DB 설정값**으로 관리하고, 앱 내에 "노무사 상담 권장" 안내를 둡니다.

### 2.4 메뉴 홍보 포스터 제작

**목표**: 디자인 툴 없이 3분 안에 인스타·매장 POP 완성.

| 단계 | 내용 |
|---|---|
| 1. 메뉴 선택 | 등록된 메뉴에서 선택 → 이름·가격·사진 자동 불러오기 |
| 2. 목적 선택 | 신메뉴 출시 / 시즌 한정 / 할인 이벤트 / 오늘의 추천 |
| 3. 카피 생성 | AI가 헤드라인·서브카피 3안 생성 (리뷰에서 자주 나온 칭찬 키워드 활용) |
| 4. 템플릿 | 매장 브랜드 컬러·로고 적용된 템플릿, 사이즈: 인스타 피드(1:1)·스토리(9:16)·A4 POP·배민 메뉴 이미지 |
| 5. 출력 | PNG/PDF 다운로드, 인스타 공유 |

**데이터 연결**: 메뉴 분석(2.6)에서 "숨은 고마진 메뉴(Puzzle)"로 분류된 메뉴를 **"홍보 추천"으로 자동 제안** → 포스터 1탭 생성.

구현 옵션: 자체 템플릿 엔진(HTML/Canvas → 이미지) 우선, 고급 디자인은 Canva Connect API 연동 검토. 메뉴 사진 배경 제거·보정은 이미지 AI 활용.

### 2.5 매출 및 순수익 계산

**목표**: "오늘/이번 달 실제로 얼마 남았나"를 매일 보여준다.

**매출 입력 경로 (상류)**
1. POS 연동 (토스플레이스·포스뱅크·OKPOS 등 — 제공사별 API/엑셀 내보내기 확인 필요)
2. 배달앱 정산 내역 엑셀 업로드 (배민·쿠팡이츠·요기요)
3. 수기 입력 (마감 시 일매출 입력) — MVP 기본

**손익 구조**
```
총매출
 − 부가세(매출세액)
 = 순매출
 − 재료원가(메뉴별 판매수량 × 레시피 원가)   ← 2.2에서 자동
 − 플랫폼·결제 수수료
 = 매출총이익
 − 인건비(급여 + 주휴 + 4대보험 사업주분)     ← 2.3에서 자동
 − 고정비(임대료·관리비·통신·감가상각·POS 이용료)
 − 변동비(전기·가스·소모품·마케팅)
 = 영업이익(순수익)
```

| 화면 | 내용 |
|---|---|
| 오늘 대시보드 | 매출, 객단가, 주문수, 시간대별 매출, 추정 순이익 |
| 월간 손익 | 위 손익구조 표 + 전월/전년 대비 |
| 손익분기점 | "이번 달 고정비를 넘기려면 하루 평균 ○○원 / 라떼 ○○잔" |
| 채널 비교 | 홀 vs 배달 채널별 실질 마진 비교 |
| 세금 대비 | 부가세 예상액 적립 알림(분기), 종합소득세 대비 월별 적립 가이드 |

### 2.6 인기·비인기 메뉴 분석 및 메뉴 조정

**목표**: "무엇을 밀고, 무엇을 고치고, 무엇을 뺄지" 데이터로 결정.

**메뉴 엔지니어링 매트릭스 (판매량 × 단위 마진)**

| | 마진 높음 | 마진 낮음 |
|---|---|---|
| **판매량 높음** | ⭐ **Star** — 유지, 대표메뉴화 | 🐴 **Plowhorse** — 가격 소폭 인상 / 레시피 원가 절감 |
| **판매량 낮음** | 🧩 **Puzzle** — 홍보 강화, 메뉴판 위치 개선 → 포스터 추천 | 🐶 **Dog** — 단종 또는 리뉴얼 후보 |

- 기준선: 판매량은 (1/메뉴수 × 70%) 점유율, 마진은 가중평균 마진
- 추가 지표: 요일·시간대별 판매, 함께 팔리는 조합(장바구니 분석 → 세트 메뉴 제안), 시즌 추세, **리뷰 감정 점수(2.1에서 유입)**
- **조정 제안 카드 예시**
  - "🐶 얼그레이 케이크: 최근 8주 판매 하위 10%, 원가율 41%. → 단종 시 월 재료 폐기 약 6만원 절감 예상"
  - "🐴 아이스 아메리카노: 판매 1위, 마진 하위권. 300원 인상 시 판매 5% 감소 가정에도 월 +○○만원"
  - "🧩 흑임자 라떼: 마진 1위, 노출 부족. → 포스터 만들기 / 메뉴판 상단 배치"
- 제안 실행 후 **2~4주 뒤 효과 측정**(전후 비교)까지 자동으로 리포트 → 의사결정 루프 폐쇄

## 4. 시스템 아키텍처 & 기술 스택 (제안)

| 계층 | 선택 | 이유 |
|---|---|---|
| 앱 | **Next.js (PWA)** → 이후 React Native/Expo 고려 | 웹 하나로 사장님·알바 모바일 동시 지원, 앱스토어 심사 없이 빠른 배포 |
| 백엔드/DB | **Supabase (Postgres + Auth + Storage + Edge Functions)** | 소규모 팀에 적합, RLS로 매장별 데이터 격리 |
| AI | Claude API (리뷰 답글·홍보 카피·메뉴 제안 문장) | 한국어 문장 품질, 톤 제어 |
| 이미지 | 서버측 HTML→PNG 렌더링(Satori/Playwright) + 이미지 생성 AI | 포스터 템플릿 |
| 배치 작업 | 일 마감 집계, 주간 메뉴 분석, 리뷰 수집 스케줄러 | Cron / Edge Functions |
| 알림 | 카카오 알림톡 / 웹 푸시 | 급여명세서, 원가율 경고, 신규 부정 리뷰 |

**권한 구조**: 사장님(Owner) / 매니저(Manager) / 알바(Staff) — 알바는 본인 근태·스케줄·급여명세만 조회.

## 6. 개발 로드맵

| 단계 | 기간 | 범위 | 완료 기준 |
|---|---|---|---|
| **Phase 0 — 기반** | 1주 | 프로젝트 셋업, 인증, 매장/권한, 디자인 시스템 | 로그인 후 매장 생성 |
| **Phase 1 — 숫자의 상류 (MVP)** | 3주 | ② 원가 계산 + ⑤ 매출 수기/엑셀 입력 + 월 손익 | 실제 카페 1곳의 메뉴 원가율·월 순이익 산출 |
| **Phase 2 — 사람** | 2주 | ③ 근태(QR/GPS) + 급여·주휴수당 계산 → 손익에 인건비 자동 반영 | 알바 3명 1개월 급여 자동 계산 일치 |
| **Phase 3 — AI 자동화** | 2주 | ① 리뷰 답글 생성(붙여넣기 방식) + ⑥ 메뉴 매트릭스·제안 | 리뷰 답글 승인율 80% 이상 |
| **Phase 4 — 홍보 루프** | 2주 | ④ 포스터 제작 + Puzzle 메뉴 홍보 추천 연결 | 포스터 생성 3분 이내 |
| **Phase 5 — 연동 확장** | 지속 | POS API, 배달앱 정산 자동 수집, 리뷰 수집 자동화(약관 검토 후) | 수기 입력 0 |

**우선순위 근거**: 원가·매출(상류 데이터)이 없으면 메뉴 분석·순이익이 무의미하므로 가장 먼저 구축합니다. 리뷰 답글은 체감 가치가 크지만 외부 API 제약이 있어 "붙여넣기 방식"으로 빠르게 가치를 검증합니다.
